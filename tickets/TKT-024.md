## Description

Memperbaiki celah kritis VULN-01 (Host API Key Exfiltration via Registry Injection) dan VULN-07 (Non-Atomic Registry Persistence) yang ditemukan dalam audit keamanan `docs/private/SECURITY_AUDIT.md`. Mencegah penyerang menyuntikkan nama variabel lingkungan arbitrer pada `api_key_env` serta memastikan penulisan file YAML konfigurasi registry bersifat atomik menggunakan pola temporary file + rename.

## Acceptance criteria

- [x] Skema `ModelSpecSchema` di `src/engine/registry.ts` membatasi `api_key_env` hanya pada allowlist yang diizinkan (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`) atau null/undefined; input arbitrer seperti `AWS_SECRET_ACCESS_KEY` ditolak dengan error validasi Zod
- [x] Validasi `base_url` di `src/engine/registry.ts` mewajibkan format URL valid berprotokol `http:` atau `https:`
- [x] Metode `ModelRegistry.saveToFile()` di `src/engine/registry.ts` diubah menjadi atomik dengan menulis ke file sementara (`${filePath}.tmp.${Date.now()}`) lalu memindahkannya via `fs.renameSync()`
- [x] Endpoint `POST /api/registry/model` dan `PUT /api/registry/model/:id` memvalidasi `api_key_env` terhadap allowlist sebelum menyimpannya ke in-memory registry dan disk
- [x] Unit test di `tests/unit/registry.test.ts` memverifikasi penolakan model spec dengan `api_key_env` di luar allowlist
- [x] Unit test memverifikasi operasi `saveToFile()` tidak merusak file konfigurasi jika terjadi kegagalan parsial
- [x] Semua tes vitest terkait registry lulus 100%
